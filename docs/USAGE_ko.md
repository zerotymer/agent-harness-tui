# agent-harness-tui: 설치와 사용

`agent-harness-tui`는 실행한 프로젝트에 에이전트 하네스를 구성하는 터미널 마법사다. 지시서 폴더, 에이전트 지침(`AGENTS.md`, `CLAUDE.md`와 각 `_ko.md` 쌍), `.skills/` 아래의 공유 스킬, `.gitignore` 블록을 만든다. 모든 변경은 먼저 미리보기로 보여 주고, 사용자가 확인할 때만 쓴다.

이 문서는 1단계(최초 생성)와 지금까지 구현한 2단계 기능을 다룬다. 2단계 기능은 프로젝트 구성(`project.json` 또는 내장 기본값), 에이전트 감지·설치, skills CLI로 공개 스킬 설치, 위키 스킬·문서·훅 목록 표시다. 이미 만든 하네스의 갱신은 이후에 제공한다.

## 설치

필요 조건: Node.js 22.13 이상(`npm` 포함).

GitHub Release마다 `npm pack` 타르볼(`agent-harness-tui-<버전>.tgz`)과 확인용 `SHA256SUMS`가 올라간다. URL이나 내려받은 파일로 전역 설치한다:

```sh
npm install -g https://github.com/zerotymer/agent-harness-tui/releases/download/v<버전>/agent-harness-tui-<버전>.tgz
```

npm 레지스트리에는 공개하지 않는다. 소스에서 빌드하려면 pnpm이 필요하다(`corepack enable`로 켠다):

```sh
pnpm install
pnpm build                      # dist/에 JavaScript 생성
pnpm pack                       # agent-harness-tui-<버전>.tgz 생성 후 npm install -g ./agent-harness-tui-<버전>.tgz
```

관리자 권한은 필요 없다. 네트워크는 위키 게이트웨이에서 스킬을 가져올 때만 필요하다.

## 실행

```sh
cd /path/to/your/project
agent-harness-tui
```

- 현재 디렉터리가 프로젝트 루트다. 상위 폴더를 찾지 않고, 브랜치를 바꾸지 않으며, `git init`을 실행하지 않는다.
- 모든 화면의 머리글에 프로젝트 루트와 쓰고 있는 구성(`project.json` 또는 내장 `default.json`, `catalog_version` 포함)이 나온다.
- 표준 입력과 출력이 모두 대화형 터미널이어야 한다. 아니면 기다리지 않고 종료 코드 2로 바로 끝난다.
- `agent-harness-tui --version`은 버전을, `--help`는 사용법을 출력한다.
- 이미 초기화된 프로젝트(`harness.toml`이 있음)는 요약과 무변경 검증을 보여 주고, 스킬 추가, 훅 추가, 오래된 지침 갱신만 연다("다시 실행할 때" 참고).

## 5단계

| 단계 | 하는 일 |
| --- | --- |
| 1. 에이전트 | 설치된 에이전트를 확인하고, 구성할 에이전트를 고르고, 없는 에이전트를 설치한다("에이전트" 참고). 고른 에이전트마다 **복사**(에이전트가 찾는 위치로 스킬 복사) 또는 **참조**(지침에서 `.skills/` 안내) 중 하나를 고른다. 심볼릭 링크 배치는 이유와 함께 선택 불가로 표시된다. 고른 에이전트 중 하나 이상이 설치되어 있어야 다음으로 간다. |
| 2. 경로·백로그 | 지시서 폴더(필수, 기본 `instructions/`, `.completed/`와 `completed.log`가 그 아래에 생김), 임시 산출물 폴더(기본 `.artifacts/`, Git 제외), 산출물(문서) 폴더(기본 `docs/`), 참조 문서 폴더(기본 `references/`)를 정한다. 이름 형식은 강제하지 않으며, 앞의 `.`은 폴더를 숨길 뿐이다. 선택 폴더를 비우면 사용하지 않는다: 만들지 않고, `.gitignore`와 지침에도 적지 않는다. 초깃값은 `project.json`의 `paths`에서 오며 `null`이면 사용 안 함으로 시작한다. TUI는 폴더를 만들기만 하므로, 경로를 바꿔도 예전 폴더는 그대로 남는다. 선택 사항인 `agent.db` 백로그 사용 여부를 고른다. 사용하면 지시서 폴더에 `agent.db`, `agent-db.sh`, `agent-db.ps1`이 생긴다(기존 DB는 그대로 둔다). 스크립트를 쓰려면 `sqlite3` CLI가 필요하다. 인자 없이 실행하면 명령 목록이 나오고, `AGENT_DB_ACTOR`를 설정하면 변경자가 기록된다. 고정 경로는 목록으로 보여 주지만 바꿀 수 없다. |
| 3. 소스·스킬 | 필요하면 프로젝트 안의 로컬 폴더나 위키 게이트웨이에서 스킬을 추가한다. "스킬 소스" 참고. |
| 4. 미리보기 | 모든 디렉터리와 파일을 생성·갱신·변경 없음·보존·충돌(CONFLICT)로 표시해 보여 주고, Git 경고도 함께 보여 준다. 아직 아무것도 쓰지 않은 상태다. |
| 5. 적용·결과 | 미리보기에서 Enter를 누르면 적용한다. 결과 화면에는 생성·갱신·변경 없음·보존 항목과 백업 폴더가 나온다. |

키: ↑↓ 이동, Space 선택, Enter 다음 단계(1·3단계에서는 선택한 버튼 실행), Esc 이전(에이전트 단계에서는 종료), Ctrl+C 취소, 입력 칸 밖에서 `q` 종료. PgUp/PgDn으로 미리보기를 스크롤한다. 경로와 이름 칸에는 한글을 입력할 수 있다. 창 크기가 바뀌면 화면이 맞춰지고, 80칸보다 좁으면 단계 목록이 한 줄로 접힌다.

## 생성되는 것

| 경로 | 용도 | Git |
| --- | --- | --- |
| `instructions/`, `instructions/.completed/` | 작업 지시서 (지시서 루트, 2단계에서 변경 가능) | 추적. 단 루트 바로 아래 `instructions/*.md`는 제외(진행 중 지시서는 로컬에만, `README.md`는 추적) |
| `instructions/completed.log` | 완료 로그. 없을 때만 빈 파일로 만들고, 고쳐 쓰지 않음 | 추적 |
| `docs/` (변경 가능, 선택) | 사용자가 공개하는 문서. 주로 HTML과 문서 | 추적 |
| `references/` (변경 가능, 선택) | 에이전트용 문서 | 추적 |
| `.gitkeep` | 도구가 새로 만든 추적 폴더마다 두는 빈 파일. Git이 빈 폴더를 유지하게 함. 덮어쓰지 않고 소유하지 않음 | 추적 |
| `.skills/<id>/` | 공유 스킬 패키지 | 추적 |
| `AGENTS.md`, `AGENTS_ko.md` (Codex) / `CLAUDE.md`, `CLAUDE_ko.md` (Claude Code) | 관리 지침 블록. 나머지 내용은 사용자 소유 | 추적 |
| `.claude/skills/<id>/`, `.agents/skills/<id>/` | 복사 배치를 고른 에이전트의 스킬 복사본 | 제외 (다시 생성됨) |
| `harness.toml`, `harness.lock.json` | 공유 설정과 확정된 가져오기 | 추적 |
| `.harness/state.json`, `.harness/backups/` | 로컬 적용 상태와 백업 | 제외 |
| `.harness/local.toml` | 선택 사항인 게이트웨이 토큰(Unix에서는 소유자만 접근) | 제외 |
| `.artifacts/` (변경 가능, 선택) | 사용자와 소통하기 위한 임시 산출물. 공유하지 않으며 다시 입력으로 읽지 않음. Windows에서 이름이 `.`으로 시작하는 새 폴더는 숨김 속성도 시도하고, 실패는 알리기만 함 | 제외 |
| `.gitignore` | 위 제외 규칙을 담은 관리 블록. 사용자의 다른 규칙은 그대로 둠 | 추적 |

도구는 기존 파일을 `agent-harness:begin`으로 시작해 `agent-harness:end`로 끝나는 관리 블록 안에서만 바꾼다. 마커가 손상됐거나 사용자가 블록 안을 수정했다면 미리보기에서 충돌로 표시하고, 파일 전체를 다시 쓰지 않는다. 파일 형식은 [`references/HARNESS_STATE_CONTRACT_ko.md`](../references/HARNESS_STATE_CONTRACT_ko.md)에 정리되어 있다.

## 스킬 소스

- **로컬 폴더.** 프로젝트 안의 폴더(예: `vendor/skills`)를 쓴다. `SKILL.md`가 있는 하위 폴더가 각각 스킬이다. 동봉 파일은 복사만 하고 실행하지 않는다. 패키지 밖을 가리키는 심볼릭 링크는 거부한다. 프로젝트 밖 폴더는 공유 설정에 저장할 수 없으므로, 그런 스킬은 먼저 프로젝트 안으로 복사한다.
- **위키 게이트웨이(`md.zerotymer.net`).** 도구는 게이트웨이 `https://md-gw.zerotymer.net`에서 `GET /api/v2/documents/<uuid>`(게이트웨이 API v2)로 읽는다.
  - **토큰(선택):** 지금은 읽기에 토큰이 필요 없다. 토큰 행에 토큰을 입력할 수 있다. 입력한 값은 화면에 그리지 않고, 적용에 성공한 뒤 Git이 무시하는 `.harness/local.toml`에 저장한다. 토큰 변수 행에 적은 환경변수(기본값 `GATEWAY_TOKEN`)에 토큰이 있으면 입력하거나 저장한 토큰보다 우선한다. 게이트웨이가 401/403으로 응답하면 토큰을 넣는다. 토큰은 추적 파일, 화면, 오류 메시지에 나오지 않는다.
  - **유형:** 선택 사항인 Wiki.js 경로 접두어(예: `skill`, `claude/hook`).
  - **조회:** 페이지 UUID를 입력하고 [조회]를 누른다. 네트워크는 그때만 쓴다. 요청은 15초가 지나면 시간 초과로 끝난다. 응답이 올 때까지 키 안내 줄에 "처리 중…"이 나오고 다른 키는 무시한다.
  - **내용:** 영문·한국어 페이지를 가공 없이 `SKILL.md`, `SKILL_ko.md`로 저장한다. 한 언어가 빠졌으면 부분 가져오기를 수락해야 하며, 빠진 번역을 만들어 내지 않는다.
  - **목록:** [목록 불러오기]는 프로젝트 구성의 `wiki_skills`를 보여 준다. 고르면 UUID, type, 스킬 이름이 채워지고, 보관된 항목과 이미 가져온 항목은 막는다. UUID를 직접 입력해도 된다.

## 프로젝트 구성

TUI는 프로젝트 루트의 `project.json`을 읽는다. 없으면 패키지에 들어 있는 `default.json`(이 저장소의 `catalog/default.json`)을 읽는다. 두 파일은 병합하지 않으며, TUI는 어느 쪽도 내려받지 않는다. 형식은 [`references/HARNESS_CATALOG_CONTRACT_ko.md`](../references/HARNESS_CATALOG_CONTRACT_ko.md)에 있다: `agents`, `skills`, `wiki_skills`, `docs`, `hooks`와 선택적인 `paths`·`service` 초깃값.

모르는 키, 지원하지 않는 `schema_version`, 중복 `id`, 옵션처럼 보이는 값, 빈 인자 배열이 있는 파일은 거부한다. 잘못된 `project.json`은 오류로 보여 주며 `default.json`으로 대신하지 않는다. 파일을 고친 뒤 다시 실행한다.

스킬 단계의 [카탈로그 보기]는 목록을 보여 준다. 공개 스킬은 설치 가능, 사용 불가(`npx` 없음), 충돌, 직접 설치 중 하나로 표시한다. 위키 스킬과 훅은 여기서는 목록만 보여 준다. 위키 스킬은 위키 소스의 [목록 불러오기]로 가져오고, 훅은 [훅 추가]로 기록한다. 문서는 여기서 Enter나 Space로 고른다(내려받기 가능, 선택됨, 내려받음, 참조 문서 경로를 쓰지 않으면 사용 불가). 고른 문서는 미리보기 직전에 내려받아 `<references>/<filename>`에 저장한다. 내려받기 실패나 `sha256` 불일치는 미리보기에 보고하고 제외하며, `sha256`이 없는 항목은 경고와 함께 저장한다. 내용이 다른 기존 파일은 충돌이며 덮어쓰지 않는다. 내려받은 결과는 `harness.lock.json`의 `docs`에 기록하며, 내려받은 문서는 다시 고를 수 없다.

## 에이전트

에이전트 목록은 구성의 `agents`에서 온다. 내장 기본값에는 Claude Code(`claude --version`, `npm install -g @anthropic-ai/claude-code@latest`)와 Codex(`codex --version`, `npm install -g @openai/codex`)가 있다.

- **감지:** 에이전트마다 `detect` 명령을 셸 없이 병렬로 실행하며 제한 시간은 5초다. 종료 코드 0이면 설치된 것으로 보고, 출력 첫 줄을 버전으로 보여 준다. [다시 감지]로 다시 실행한다.
- **프로그램 찾기:** `PATH`만 쓴다. Windows에서는 `PATHEXT` 확장자도 시도하므로 `npm`이 `npm.cmd`를 찾는다.
- **설치:** 감지되지 않은 에이전트를 고르고 [설치]를 누른다. 확인 화면에 이 OS에서 실행할 명령 전체가 에이전트마다 나온다. Enter를 누르면 터미널을 넘기고 하나씩 차례로 실행한다. 끝나면 Enter를 눌러 돌아오고, TUI가 종료 코드를 각각 보여 준 뒤 다시 감지한다. 0이 아니면 실패다.
- npm 전역 설치다. `PATH`에 npm이 있어야 하고, Claude Code는 Node.js 22 이상이 필요하며, npm prefix에 쓸 권한이 없으면 `EACCES`로 실패한다. TUI는 `sudo`나 권한 상승을 쓰지 않는다. 셸 설치 스크립트(`curl … | bash`)는 지원하지 않는다.
- 이 OS용 설치 명령이 없는 에이전트는 설치를 사용 불가로 표시한다.
- `harness.toml`에는 고른 에이전트 ID를 저장한다. 지침 파일과 스킬 디렉터리는 에이전트 항목에서 가져온다. 지침 파일이 같은 에이전트는 관리 블록 하나를 함께 쓰고, 에이전트별 내용은 블록 하단에 에이전트 이름 아래로 붙는다.
- `harness.toml`에 있지만 구성에 더 이상 없는 에이전트 ID는 그대로 두고 "알 수 없음"으로 표시하며, 지침과 스킬 복사본을 만들지 않는다.

## 공개 스킬 설치

[카탈로그 보기]에서 공개 스킬로 이동해 Enter를 누르면 확인 화면이 열린다. 화면에는 실행할 명령이 그대로 나온다. 명령은 카탈로그 항목의 필드로 만들며, 카탈로그의 명령 문자열을 쓰지 않는다.

```text
npx skills add <source> [-s <skill>]
```

- 항목에 `skill`이 없거나 `*`이면 `-s`를 빼며, 이때 CLI가 source의 모든 스킬을 보여 준다.
- TUI는 `-a`, `-g`, `-y`를 붙이지 않는다. Enter를 누르면 TUI 화면을 닫고 터미널을 skills CLI에 넘긴다. 대상 에이전트, project·user 범위, 스킬은 CLI가 직접 묻는다. CLI가 끝나면 Enter를 눌러 돌아오고, TUI가 종료 코드를 보여 준다. 0이 아니면 실패다.
- 셸 없이 프로젝트 루트에서 실행한다(Windows는 `npx.cmd`). `PATH`에 `npx`가 없으면 설치를 사용 불가로 표시한다.
- 버전을 고정하려면 카탈로그가 CLI 문법으로 `source`에 적는다(예: `owner/repo@<커밋 SHA>`).
- 이름 충돌: 항목의 `skill`이 하네스가 배포했거나 선택한 스킬과 같으면(대소문자 무시) 설치를 막는다. 모든 스킬을 설치할 때는 이름을 미리 알 수 없으므로, 검사를 할 수 없다고 화면에서 경고한다.
- skills CLI가 설치한 것(예: `.agents/skills/`, `.claude/skills/` 아래 링크, `skills-lock.json`)은 CLI가 관리한다. 하네스는 그 파일을 추적하거나 지우지 않는다.
- 다른 설치 도구 항목(예: `claude plugin`)은 직접 실행할 명령만 보여 준다.

skills CLI 1.9.0으로 확인함(2026-11-23): 빈 프로젝트에서 `npx skills add anthropics/skills@<커밋 SHA> -s pdf`를 실행하자 `.agents/skills/pdf`가 설치되고, `.claude/skills/pdf`에 링크되었으며, `skills-lock.json`에 커밋이 기록되었다. 이 실행은 코딩 에이전트 안에서 했고, 그 환경에서는 CLI가 질문하지 않는다. 일반 터미널에서의 대화형 질문은 아직 수동으로 확인해야 한다.

## 다시 실행할 때

스키마 1로 쓴 `harness.toml`(`output` 사용)도 읽는다. `output`은 값 그대로 `artifacts`가 되므로 기존 `.output/`을 계속 쓴다. 스킬이나 훅을 추가하는 등 다음 적용 때 스키마 2로 다시 쓴다.

`harness.toml`이 있으면 요약을 보여 주고, 파일이 설정과 일치하는지 검증한다. 여기서는 경로와 에이전트를 바꿀 수 없다. 검증에 충돌이 없으면 다음 버튼을 보여 준다.

- **[스킬 추가]**: 기록된 경로와 에이전트로 소스·스킬 화면을 연다. 로컬 폴더, 위키 스킬(목록 버튼이 구성의 `wiki_skills`를 보여 주며, 보관된 항목과 이미 가져온 항목은 막는다), 공개 스킬 중에서 추가한다. Esc를 누르면 검증 화면으로 돌아간다.
- **[훅 추가]**: 구성의 `hooks`를 보여 준다. 고른 ID를 `harness.toml`에 기록하고, 지침에 "훅(참고)" 절을 만들어 사용하는 훅을 에이전트 설정에 직접 추가하고 조정하라고 안내한다. 아무것도 설치하거나 실행하지 않는다.
- **[지침 갱신]**: 지침 블록이 현재 구성으로 만든 내용과 다를 때만 보인다. 예를 들어 이 도구의 새 버전을 쓰거나 `project.json`에서 훅 이름이 바뀐 경우다. 미리보기 후 관리 블록을 다시 쓰며, 블록 밖의 사용자 글은 그대로 둔다. 미리보기에서 Esc를 누르면 쓰지 않고 검증 화면으로 돌아간다. 사용자가 직접 고친 블록은 충돌이며, 그때는 버튼을 보여 주지 않는다.

모든 작업은 평소처럼 미리보기와 적용을 거치며 더하기만 한다. 이미 설치한 스킬은 다시 추가할 수 없고, 스킬 갱신·삭제는 이후에 제공한다. 같은 초기화를 반복해도 블록, 스킬, ignore 규칙이 중복되지 않는다.

## 복구

- 기존 파일을 바꾸기 전에 `.harness/backups/<apply-id>/`에 사본을 남긴다.
- 쓰기가 실패하면 이미 쓴 파일을 되돌리고, 새로 만든 파일과 빈 폴더를 지운다. 되돌리지 못한 항목은 목록으로 보여 주며, 성공으로 기록하지 않는다.
- 비정상 종료로 `.harness/apply.lock`이 남으면, 사용자가 지울 때까지 적용을 거부한다. 다른 실행이 없을 때만 지운다.
- 도구는 커밋·푸시를 하지 않는다. 제외 대상 경로를 Git이 이미 추적 중이면 `git rm --cached`를 직접 실행하라고 안내한다.
