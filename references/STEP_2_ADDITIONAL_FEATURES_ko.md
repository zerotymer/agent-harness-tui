# 2단계: 하네스 추가 기능

## 선행 조건 및 목표

애플리케이션 저장소에서 [1단계](STEP_1_INITIAL_CREATION_ko.md) 완료 기준을 충족한 뒤 시작한다. 독립 실행형 TUI에 제한된 업데이트, 설정 override, 모드, 훅, 선택적 Git worktree 연동을 추가한다. 선택 도구 없이도 1단계 초기화를 사용할 수 있어야 한다.

이 지시서는 외부 백엔드 서비스, 스케줄러, 중앙 백로그 서비스, 범용 컨테이너 관리 제품 구축을 지시하지 않는다.

## 1. 제한된 하네스 업데이트

변경 가능 범위를 다음으로 제한한다.

- 선택한 스킬과 관리 대상 에이전트 배포본의 추가·삭제·명시적 갱신
- 관리 훅의 추가·수정·비활성화·삭제
- 지원되는 연동 프로필 및 모드 프로필의 활성화·비활성화
- 영향을 받는 관리 지침 블록과 호환되는 설정·상태 메타데이터 재생성

애플리케이션 소스, 사용자 작성 지시서, 참조 문서, 지시서 로그, DB 내용을 변경하지 않는다. 업데이트 기능으로 프로젝트 루트나 1단계 디렉터리 구성을 이동·변경하지 않는다. 경로 마이그레이션은 별도 향후 기능이며 프로필 적용에 암묵적으로 포함하지 않는다.

적용 전 목표 설정, 마지막 적용 기준, 현재 파일 내용을 비교한다. 추가·변경·삭제·충돌·소유권을 표시한다. 사용자 수정 내용을 자동 덮어쓰거나 삭제하지 않는다. 스킬 삭제는 해당 배포가 소유한 파일에만 영향을 주며 무관한 내용을 보존한다.

1단계 메타데이터를 버전 관리하고 백업과 함께 변환한다. 적용 성공 후에만 성공 상태를 확정한다. 반복 적용은 무변경이어야 하며 중간 실패 복구를 제공한다. 연동 해제는 관리 설정만 제거하며 worktree·컨테이너·네트워크·볼륨·DB를 삭제하지 않는다.

## 2. Override 모델

다음은 외부 도구가 아니라 하네스 자체의 적용 순서다.

```text
내장 기본값
  -> 활성화한 연동 기본값
  -> 프로젝트 override
  -> 환경/worktree별 로컬 override
  -> 이번 실행에서만 선택한 값
```

- 공유 선택·프로젝트 override는 `harness.toml`, 가져온 확정 버전은 `harness.lock.json`에 저장한다.
- 비밀이 아닌 환경/worktree별 override에 `.harness/local.toml`을 도입한다. 로컬 적용 상태와 함께 Git에서 제외한다.
- 이번 실행의 선택은 명시적으로 저장하지 않으면 일시적이다. 임시 모드 전환 때문에 공유 지침을 다시 써서 불필요한 Git 변경을 만들지 않는다.
- 기능별 허용 override 키를 정의한다. 프로필로 고정 경로나 변경 범위 제약을 우회하지 못하게 한다.
- 단일값은 나중 설정이 우선한다. 스킬·훅은 안정적인 ID를 키로 삼고 명시적 비활성화·삭제를 지원한다. 목록을 무작정 합치거나 같은 명령을 두 번 등록하지 않는다.
- 활성 연동 기본값끼리 충돌하면 명시적으로 해결하며 우연한 순회 순서에 의존하지 않는다.
- 최종값, 값을 결정한 계층, 생성 예정 변경을 미리보기에 표시한다.
- 확정된 모델을 각 도구의 실제 설정 의미로 변환한다. 특히 Worktrunk 훅은 자체 설정 계층에서 누적될 수 있으므로 하네스의 값 교체가 외부 훅 교체로 이어진다고 가정하지 않는다.

## 3. 모드

분석·구현·검토 프로필을 프로젝트 정책으로 제공한다. 각 프로필은 관련 지침·스킬·지원되는 검사를 선택한다. 프로젝트 기본 프로필과 이번 실행의 선택을 구분한다.

프로필이 지침만 반영하는지, 지원되는 에이전트 권한·샌드박스 설정도 적용하는지 명시한다. Markdown 규칙이 읽기 전용 동작을 강제한다고 주장하지 않는다. 에이전트별 지원 방식·버전을 확인하고, 지원하지 않는 강제 기능은 사용 불가로 표시한다. 지침으로 대체하면서 같은 강제 효과를 보장한다고 안내하지 않는다.

지원되는 세션 방식으로 모드를 전환하거나 재시작이 필요하면 안내한다. 동작을 검증하지 않고 실행 중인 에이전트가 변경 파일을 다시 읽었다고 주장하지 않는다. 이 단계에는 모델 선택·과금 정책·자율 작업 오케스트레이션을 추가하지 않는다.

## 4. 훅 구조

하네스 자체 수명주기 훅, 에이전트 실행 훅, worktree·컨테이너 수명주기 훅을 구분한다.

| 종류 | 주체 및 목적 |
| --- | --- |
| 하네스 | 설정 적용 전후, 검증, 적용 결과 확인 |
| 에이전트 | 지원되는 세션·도구 이벤트, 프로젝트 일관성 검사, 설정된 제한 |
| worktree·컨테이너 | 선택적 Worktrunk·Docktree 수명주기 연동 |

- 우선 내장 검증 기능을 제공한다. 문서를 가져오는 과정에서 동봉 스크립트를 실행하지 않는다.
- 훅 ID, 소유 주체, 지원 이벤트, 실행 파일·인수 배열, 루트·cwd 규약, 지원 OS·에이전트 버전, 시간 제한, 동기 차단·백그라운드 여부, 실패 정책, 활성 여부를 정의한다.
- OS별 셸 코드 생성보다 구조화된 인수로 하네스 실행 파일의 하위 명령을 호출하는 방식을 우선한다. 외부 도구가 셸을 요구하면 실행 환경 의존성을 명시하고 검증한다.
- 인수·변수·경로를 데이터로 취급한다. 신뢰되지 않은 원격 내용을 셸 명령에 보간하지 않는다.
- 원격 실행 훅은 별도로 확인 가능한 활성화 절차를 둔다. 명령·출처를 미리 보여주고 외부 도구의 신뢰·승인 절차를 우회하지 않는다.
- 실행 순서와 실패 처리를 정의한다. 필수 사전 조건 실패는 해당 작업을 막는다. 선택적 후처리 실패는 보고하며 성공으로 위장하지 않는다.
- 각 동작의 수명주기 주체를 하나로 정한다. 에이전트 훅과 Worktrunk 훅에서 초기화·정리를 중복 실행하지 않는다.
- 실행 로그는 로컬에 보관하고 인증 정보를 가린다. 재귀 실행과 반복 자기 트리거를 막는다.
- 세션 종료는 작업 완료가 아니다. 종료 훅에 지시서 자동 보관이나 가짜 완료 이벤트를 추가하지 않는다. 향후 명시적 작업 흐름에서 검증된 수명주기 동작을 연결할 수 있다.
- 연결부별 최신 공식 훅 규약을 확인한다. 미지원·deprecated 이벤트를 사용 가능으로 표시하지 않으며 legacy 호환 코드를 추가하지 않는다.

## 5. Git worktree 기반을 먼저 구현하고 Worktrunk 연결

Worktrunk 연결부보다 worktree 식별·상태 분리를 먼저 구현한다. Worktrunk는 Git worktree의 선택적 관리 도구이며 프로젝트 루트 규칙을 대체하지 않는다.

- 현재 worktree 루트를 실제 프로젝트 루트로 유지한다. Git으로 공유 저장소 식별자를 별도 조회하며 `.git`이 디렉터리라고 가정하지 않는다.
- 각 worktree 내부의 관리 상대 경로를 유지한다. 지시서·참조 문서·스킬 원본은 해당 worktree의 checkout을 따르며 하나의 쓰기 가능한 전역 사본을 공유하지 않는다.
- `.output/`, `.harness/`, 선택적 `agent.db`는 기본적으로 worktree별 분리한다. SQLite 파일·인증 정보·일시 상태를 자동 공유·복사하지 않는다.
- 로컬 적용 상태가 없는 새 worktree는 추적 중인 설정·잠금 정보에서 소유권 검사를 시작한다. 추적되지 않는 진행 중 지시서가 복사된다고 가정하지 않는다.
- 고유 이벤트 ID와 추가형 지시서 로그를 유지한다. 브랜치 병합 시 로그·순번 충돌을 검출하며 전역 순번을 보장하거나 이력을 몰래 고치지 않는다. 중앙 로그 서비스를 도입하지 않고 Git 병합을 명시적 작업으로 유지한다.
- Worktrunk 설치·지원 버전을 확인한다. 기본은 연동 비활성이고 설치 사실만으로 활성화하지 않는다.
- 지원되는 프로젝트 범위 설정과 관리 작업 지침·스킬만 생성한다. 현재 공식 프로젝트 설정 경로는 `.config/wt.toml`이며 구현 시 재확인한다. 기존 설정을 보존하고 자체 훅 누적 효과를 표시한다.
- 사용자 홈 설정이나 셸 시작 파일을 프로젝트 설정 과정에서 몰래 바꾸지 않는다. 필요한 셸 연동·의존성은 별도로 안내한다.
- worktree 생성·전환·제거 연동 동작은 명시적으로 수행한다. 프로필을 바꿀 때 자동 병합·브랜치 삭제·worktree 제거를 하지 않는다.
- Git Bash 의존성과 실행 파일명 충돌 등을 포함해 최신 Worktrunk Windows 규약을 검증한다. Rust TUI가 네이티브라는 이유로 외부 훅 실행 환경까지 자동으로 다중 OS를 지원한다고 주장하지 않는다.

## 6. 선택적 Docktree 연동

- worktree별 상태 분리와 검증된 Docktree·Docker Compose 전제조건을 요구한다. Worktrunk 활성화를 요구하지 않는다. 다른 방법으로 worktree를 관리할 수도 있다.
- Worktrunk·Docktree 사용 여부를 독립적으로 선택한다. 둘 다 미사용·각각 단독·동시 사용을 지원하고 의존성·상태를 미리 표시한다.
- 동시 사용 시 worktree 생성 → 로컬 하네스 준비 → 선택적 Docktree 환경 준비로 하나의 흐름을 정의한다. 중간 실패를 보고하고 같은 환경을 두 번 구성하지 않는다.
- 구현 전 최신 Docktree 설정·상태 경로·플랫폼 지원·수명주기 명령을 검증한다. 선택한 구성에 필요한 관리 프로젝트 설정·문서만 생성한다.
- 하네스 설정 override와 Docktree가 생성하는 Compose override를 구분한다. 원본 Compose 파일을 보존하며 경쟁하는 자체 자원 할당 레지스트리를 만들지 않는다.
- 포트, 컨테이너·프로젝트 식별자, 볼륨 등 실행 자원은 Docktree 상태를 기준으로 조회한다. TUI에는 연동 참조와 마지막 관측 상태만 로컬 저장한다.
- 환경 시작·종료는 설정 갱신과 별도로 미리 보여준다. 프로필 선택이나 스킬 가져오기만으로 컨테이너를 시작하지 않는다.
- 연동 비활성화 시 자원 정리를 호출하지 않는다. worktree·볼륨 삭제는 자원 미리보기를 제공하는 명시적 명령의 범위다.
- 미지원 OS·도구 버전은 미지원으로 표시한다. 이 지시서는 legacy 에뮬레이션 계층을 요구하지 않는다.

## 7. 외부 시스템: 기획상 연계 경계만 정의

다음 선택적 시스템과 연결 경계를 문서화한다. 이 지시서로 새로 구축·배포하지 않는다.

| 후보 | 기대 역할 |
| --- | --- |
| `md.zerotymer.net` 등 스킬·지침 소스 | 목록, 문서, 리비전, 인증 |
| 훅·하네스 템플릿 저장소 | 재사용 프로필, 플랫폼·에이전트 호환 정보 |
| 백로그·작업 상태 시스템 | 선택적 지시서 연결. `agent.db` 규약은 1단계 명세 §2(이슈 #21)를 따른다. 스키마를 바꾸려면 사용자가 새 규약을 제공해야 한다 |
| 인증 정보 관리 수단 | 실제 토큰을 프로젝트 공유 파일과 분리 |

연결 확인, 시간 제한, API·버전별 기능 표시, 오래된 캐시 처리를 정의한다. 외부 장애에도 기존 로컬 문서를 사용할 수 있어야 한다. TUI 작동에 데몬·웹 서버·큐·중앙 DB를 요구하지 않는다.

여러 머신·worktree에 걸친 SQLite 공유나 범용 레지스트리 API를 가정해 구현하지 않는다. 해당 규약은 별도 향후 연계 지시서에서 정의한다.

## 8. TUI 추가 화면 및 상태 저장

현재 적용 상태, 스킬·훅 업데이트, 모드, 연동 선택, 계층별 최종 설정, 충돌 해결, 복구 결과 화면을 추가한다.

안정적 ID, 소스 리비전, 활성 여부, 관리 파일·블록, 기준 해시, 복사·참조 매핑, 저장소·worktree 식별자, 지원 연결부 버전, 적용 결과를 기록한다. 공유 의도와 로컬에서 관측한 실행 상태를 분리한다.

연동이 설정됐다는 사실은 외부 실행 환경이 정상이라는 의미가 아니다. 설정됨·사용 불가·미지원·검증됨 상태를 구분해 표시한다.

## 9. 완료 기준

- Worktrunk·Docktree·Docker가 없어도 1단계 완료 기준을 계속 충족한다.
- 정해진 범위에서 스킬·훅 추가·삭제·갱신이 가능하며 충돌 감지·업데이트 취소 시 사용자 수정을 보존한다.
- override 우선순위가 결정적이고 허용 키를 강제하며 최종 설정의 출처를 확인할 수 있다.
- 로컬 상태 누락, 메타데이터 변환, 업데이트 중단을 파괴적 덮어쓰기나 거짓 성공 기록의 근거로 삼지 않는다.
- 훅 인수 처리, 시간 제한·실패 정책, 중복 실행 방지, 원격 가져오기 중 실행 금지를 테스트한다.
- 두 worktree의 산출물·DB·적용 상태가 독립적이며 상대 경로가 현재 worktree 내부에서 해석된다.
- 전제조건이 있는 환경에서 일반 Git worktree, Worktrunk 단독, Docktree 단독, 동시 사용을 검증한다. 실제 지원 도구로 검증하지 못한 연동을 명시한다.
- 연동 해제로 worktree·실행 자원이 삭제되지 않는다. 업데이트가 루트 경로나 사용자 문서를 변경하지 않는다.
- 지침만 적용하는 모드와 실제 권한 설정을 구분하며 미지원 방식을 표시한다.
- 공유 설정·잠금 정보·생성 지침의 영문·한국어가 일치한다. 추적 산출물에 인증 정보를 넣지 않는다.

## 산출물

확장된 애플리케이션, 설정·상태 마이그레이션, 관련 테스트, 영문·한국어 업데이트·연동 문서를 제공한다. 검증한 OS·에이전트·도구 호환표와 미확정 외부 규약 목록을 포함한다. 외부 서비스를 새로 구축·배포하지 않는다.
