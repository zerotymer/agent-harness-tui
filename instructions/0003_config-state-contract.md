## 목표
`harness.toml`, `harness.lock.json`, `.harness/state.json`의 버전 있는 규약을 정의하고 읽기·쓰기·검증을 구현한다. 2단계 업데이트에 필요한 기준 상태를 지금 담는다.

## 규칙 구분
- 아래 요구사항은 TUI가 **대상 프로젝트에 적용하는 제품 동작**이다. 이 저장소의 작업 규칙(`CLAUDE.md`, `.skills/`)과 혼동하지 않는다.
- 테스트는 임시 디렉터리에 대상 프로젝트를 만들어 검증한다. 이 저장소의 `instructions/`, `.gitignore`, 지침 파일을 픽스처로 쓰지 않는다.

## 범위
- 포함:
  - 모든 파일에 명시적 `schema_version`. 모르는(더 새로운) 버전은 명확한 오류, 덮어쓰지 않음
  - `harness.toml`(Git 포함): 경로, 대상 에이전트, 외부 소스 식별자, 선택 스킬, 배치 방식, 백로그 옵션(사용 여부·상대 경로)
  - `harness.lock.json`(Git 포함): 확정된 소스 ID, 리비전·내용 해시, 가져온 파일 목록
  - `.harness/state.json`(Git 제외): 마지막 성공 적용, 관리 파일·블록 소유권, 기준 해시, 복사본 매핑
  - `.harness/backups/`(Git 제외) 디렉터리 배치 규약
  - 공유 파일 검증: 토큰, 환경별 절대 경로, 일시적 할당 정보 거부
  - 소유권은 파일 또는 관리 블록 단위로 기록
  - 2단계 명세의 상태 항목(안정 ID, 소스 리비전, 관리 파일·블록, 기준 해시, 복사/참조 매핑, 어댑터 버전, 적용 결과)과 대조해 1단계에서 기록 가능한 항목 포함
  - 해시 알고리즘 기본값 SHA-256 (규약 문서에 명시)
- 제외:
  - 상태를 이용한 업데이트·마이그레이션 (2단계)
