# 2단계: 설정 플로우

## 선행 조건 및 목표

[1단계](STEP_1_INITIAL_CREATION_ko.md)가 인수 조건을 통과한 뒤에만 시작한다(2026-11-20 인수). 이 단계는 2026-11-23에 다시 정의했다(지시서 0022). 이전의 카탈로그 연동 범위를 대체한다.

TUI는 개발 환경을 네 단계로 구성한다.

1. 에이전트: 설치된 에이전트를 감지하고, 없는 에이전트를 설치한다.
2. 경로: 표준 경로를 정한다.
3. 지침: 에이전트 지침 파일을 만들거나 갱신한다.
4. 설치: 프로젝트 구성에서 스킬·위키 스킬·문서를 설치하고, 동적 스킬·참조 문서를 연결한다.

1단계 규칙은 그대로 유지한다. 현재 디렉터리가 프로젝트 루트이고, 기존 파일은 관리 블록 안에서만 바꾸며, 적용할 때마다 백업하고, 모든 쓰기가 성공한 뒤에만 성공을 기록한다.

환경의 대부분은 Git으로 공유한다. 두 가지는 예외다. 환경변수는 다른 방법으로 공유하고, 공유하면 안 되거나 실시간으로 읽어야 하는 내용은 **콘텐츠 서비스**에서 받는다. 콘텐츠 서비스는 별도 프로그램이며, 이 리포지토리는 그 클라이언트만 구현한다(§7).

범위 밖: worktree·서비스 관리, 실행형 훅, 범용 하네스 업데이터(3단계), 사용자가 제공한 `agent.db` 스키마(이슈 #21) 외의 SQLite 스키마.

## 1. 프로젝트 구성

- TUI는 프로젝트 루트의 `project.json`을 읽는다. 프로젝트 소유자가 작성하고 Git으로 관리한다.
- `project.json`이 없으면, 이 리포지토리의 `catalog/default.json`으로 실행 파일에 내장한 `default.json`을 읽는다.
- 두 파일은 병합하지 않는다. `project.json`이 있으면 `default.json`은 읽지 않는다.
- 형식은 [HARNESS_CATALOG_CONTRACT_ko.md](HARNESS_CATALOG_CONTRACT_ko.md)에 있다. `agents`, `skills`, `wiki_skills`, `docs`, `hooks` 목록과, 경로·콘텐츠 서비스의 선택적 초깃값을 담는다.
- TUI는 프로젝트 구성을 내려받지 않는다.
- 모르는 키, 지원하지 않는 `schema_version`, 중복 `id`가 있는 파일은 거부하고 오류를 보여 준다. `project.json`이 잘못되었을 때 `default.json`으로 조용히 넘어가지 않는다.
- 사용 중인 파일과 그 `catalog_version`을 보여 준다.
- **설치 명령은 사용자 책임이다.** TUI는 구성에 적힌 인자 배열을 모두 보여 주고, 사용자가 확인한 경우에만 셸 없이 실행한다. 명령 문자열은 실행하지 않는다.
- 구성 파일에는 비밀 값을 넣지 않는다. 토큰은 환경변수 이름으로만 가리킨다.
- CI는 내장 `default.json`을 TUI와 같은 검증 코드로 파싱한다.
- **실행 환경:** TUI는 Node.js 22.13 이상에서 실행한다(TypeScript + Ink, 2026-11-24. 22.13은 내장 `node:sqlite` 때문). 에이전트 설치와 스킬 설치는 같은 Node.js 설치의 npm·npx를 쓴다.

## 3. 에이전트

- 에이전트 목록은 프로젝트 구성의 `agents`에서 가져온다. 내장 `default.json`에는 Claude Code와 Codex가 있고, npm으로 설치한다(2026-11-24 공식 문서로 확인).

  | 에이전트 | `detect` | `install` (모든 OS) |
  | --- | --- | --- |
  | Claude Code | `claude --version` | `npm install -g @anthropic-ai/claude-code@latest` |
  | Codex | `codex --version` | `npm install -g @openai/codex` |

- **npm 설치의 주요 제약 사항:**
  - `PATH`에 npm이 있어야 한다. 없으면 설치를 사용 불가로 표시한다. Claude Code는 Node.js 22 이상이 필요하다.
  - npm 전역 설치다. npm prefix에 쓸 권한이 없으면 `EACCES`로 실패할 수 있다. TUI는 `sudo`나 권한 상승을 쓰지 않는다. 종료 코드를 보고하고, 사용자가 npm 설정을 고치거나 다른 방법으로 설치한다.
  - 공식 셸 설치 스크립트(`curl … | bash`, `irm … | iex`)는 지원하지 않는다. TUI는 셸을 실행하지 않는다.
- **프로그램 찾기:** `detect`와 `install`의 첫 요소는 셸 없이 `PATH`에서 찾는다. Windows에서는 `PATHEXT` 확장자도 붙여 찾으므로 `npm`, `claude`가 `npm.cmd`, `claude.cmd`를 찾는다. Node.js는 `.cmd`·`.bat` 파일을 `cmd.exe` 없이 실행하지 못하므로, 그런 파일일 때만 `cmd.exe /d /s /c <파일> <인자>`로 실행한다. 이때 어떤 인자에도 공백이나 `cmd` 특수문자(`& | < > ^ % ! " ( )`)가 없는지 먼저 검사하고, 검사에 걸리면 아무것도 실행하지 않고 거부한다. 구성의 명령 문자열을 넘기지 않으며 `shell` 옵션은 쓰지 않는다.
- **감지:** 각 에이전트의 `detect` 인자 배열을 셸 없이, 5초 제한 시간으로 실행한다. 화면이 멈추지 않도록 에이전트들을 동시에 감지하고, 제한 시간이 지나도 실행 중인 프로세스는 종료한다. 종료 코드 0이면 설치된 것이다. 출력 첫 줄을 버전으로 보여 준다.
- **선택:** 감지된 에이전트는 무엇이든 고를 수 있다. 감지되지 않은 에이전트도 설치하려고 고를 수 있으며, 여러 개를 한 번에 설치할 수 있다.
- 선택한 에이전트 중 하나 이상이 설치되어 있어야 이 단계를 벗어날 수 있다.
- **설치:** 확인 화면에 현재 OS용 인자 배열 전체를 에이전트마다 보여 준다. 확인하면 §6.1처럼 터미널을 넘겨 하나씩 설치하고, 종료 코드를 보여 준 뒤 다시 감지한다. 0이 아닌 종료 코드는 실패다.
- 현재 OS용 설치 명령이 없는 에이전트는 설치를 사용 불가로 표시한다.
- `harness.toml`에는 선택한 에이전트 ID를 저장한다. 지침 파일 이름과 스킬 디렉터리는 에이전트 항목에서 가져온다. 1단계의 ID `claude-code`, `codex`는 계속 유효하므로 스키마를 바꿀 필요가 없다.
- `harness.toml`의 에이전트 ID가 구성에 없으면 `harness.toml`에는 그대로 두고, 알 수 없음으로 표시하며, 그 에이전트에는 배치하지 않는다.
- 루트 화면은 따로 두지 않는다. 프로젝트 루트는 머리글에 표시한다.
- 이미 초기화된 프로젝트(`harness.toml`이 있음)나 파일·구성을 읽을 수 없는 프로젝트는 에이전트 화면 대신 요약과 무변경 검증을 보여 준다(2026-11-26 결정). 이 화면에서는 경로와 에이전트를 바꿀 수 없다. 검증에 충돌이 없으면 두 가지 추가 작업만 연다(지시서 0026): **스킬 추가**(소스·스킬 화면: 로컬 폴더, 위키 스킬, 공개 스킬)와 **훅 추가**(§6.4). 추가는 평소처럼 미리보기와 적용을 거치며 더하기만 한다: 새 스킬과 그 복사본, 훅 기록, 그에 맞는 `harness.toml`·`harness.lock.json`·관리 블록 갱신.
- 잘못된 `project.json`은 그 화면에 오류로 보여 주며, `default.json`으로 대신 시작하지 않는다.

## 4. 경로

모든 경로는 사용자가 바꿀 수 있다. 이름 형식은 강제하지 않는다. 기본값 앞의 `.`은 디렉터리를 숨기려는 것일 뿐이다.

| 항목 | 기본값 | 필수 | 용도 | Git |
| --- | --- | --- | --- | --- |
| 지시서 | `instructions/` | 예 | 작업 지시서 | 일부 추적(아래) |
| 임시 산출물 | `.artifacts/` | 아니요 | 사용자와 대화하기 위한 임시 아티팩트 | 제외 |
| 산출물 | `docs/` | 아니요 | 사용자가 발행한 문서. 주로 HTML과 문서 | 추적 |
| 참조 문서 | `references/` | 아니요 | 에이전트를 위한 문서. Markdown 파일 또는 사용자가 넣은 문서 | 추적 |
| 스킬 원본 | `.skills/` | 고정 | 스킬 원본. 1단계와 같음 | 추적 |

- 사용하지 않는 선택 경로는 만들지 않고, `.gitignore`에 쓰지 않으며, 지침에도 적지 않는다. 그 경로가 필요한 기능(예: 참조 문서로 문서 내려받기)은 사용 불가로 표시한다.
- 1단계의 안전 검사는 유지한다. 모든 경로는 프로젝트 상대 경로이고 루트 안에 있어야 하며, `..`이나 심볼릭 링크로 벗어날 수 없다. 관리 경로끼리 중복(대소문자 무시)·중첩되거나, 종류가 다른 기존 항목과 충돌하면 안 된다.
- TUI는 경로를 만들기만 한다. 경로를 바꾼 뒤에도 디렉터리를 옮기거나 이름을 바꾸거나 지우지 않는다. 기존 디렉터리는 그대로 남는다.
- 디렉터리 숨김은 OS에 따른 선택 기능이다. Windows에서는 새로 만든 임시 산출물 디렉터리 이름이 `.`으로 시작하면 숨김 속성을 시도한다. 실패는 정보로만 보고하며 적용을 막지 않는다. Git은 이 속성을 다른 클론에 전달하지 않는다.

**지시서 루트 아래 고정 이름:**

| 항목 | 경로 | Git |
| --- | --- | --- |
| 완료 지시서 | `<instructions>/.completed/` | 추적 |
| 완료 로그 | `<instructions>/completed.log` | 추적 |
| 백로그(선택) | `<instructions>/agent.db` | 제외 (`agent-db.sh`/`agent-db.ps1`은 추적) |

`agent.db` 규칙은 1단계 명세 §2 그대로다.

**Git:**

- 진행 중 지시서 파일은 제외한다. 관리 `.gitignore` 블록은 지시서 루트 바로 아래의 Markdown 파일을 모두 제외하고 `README.md`는 남긴다.
  ```gitignore
  /<instructions>/*.md
  !/<instructions>/README.md
  ```
  `<instructions>`는 설정한 지시서 경로(기본값 `instructions`)이므로 기본 블록은 `/instructions/*.md`, `!/instructions/README.md`다. 새 프로젝트의 임시 산출물 경로는 `.artifacts/`로 시작하며, 다른 경로처럼 사용자가 바꿀 수 있다. 이 패턴은 하위 디렉터리에 닿지 않으므로 `.completed/`, `completed.log`, `.gitkeep`, 스크립트는 계속 추적된다. 지침에 생성하는 지시서 규칙도 같은 내용을 적는다.
- 임시 산출물 디렉터리와 `agent.db*`는 제외한다.
- **`.gitkeep`:** 새로 만든 빈 디렉터리를 Git이 관리하게 하려는 용도다. TUI가 추적 대상 디렉터리를 만들면 그 안에 빈 `.gitkeep`도 만든다. 대상은 `<instructions>/`, `<instructions>/.completed/`, 산출물, 참조 문서다. 제외 대상 디렉터리에는 만들지 않는다. 이미 있던 디렉터리는 건드리지 않는다. 없을 때만 만들며 기존 `.gitkeep`은 건드리지 않는다. 빈 `completed.log`처럼 소유 파일로 기록하지 않는다.

**마이그레이션:** 스키마 1 `harness.toml`도 읽는다. `paths.output`은 값은 그대로인 채 `paths.artifacts`가 된다. 기존 `.output/`은 계속 쓰이고 계속 제외된다. 다음 적용이 성공하면 평소처럼 백업한 뒤 스키마 2로 쓴다. [HARNESS_STATE_CONTRACT_ko.md](HARNESS_STATE_CONTRACT_ko.md) 참고.

## 5. 지침

- 에이전트와 경로를 적용한 뒤, 선택한 에이전트마다 지침 파일을 만들거나 갱신한다. 파일 이름은 에이전트 항목에서 가져온다. 예를 들어 Claude Code는 `CLAUDE.md`, Codex는 `AGENTS.md`다(복수형 `AGENTS.md`이며 `AGENT.md`가 아니다). 파일마다 한국어 `_ko.md` 짝이 있다.
- 지침 파일이 같은 에이전트들은 하나로 취급한다. 그 파일에는 관리 블록이 하나만 있다. 특정 에이전트에만 해당하는 내용이 있으면 블록 하단에 그 에이전트 제목 아래 덧붙인다.
- 블록에는 사용하는 경로와 용도, 지시서 규칙, Git 정책, 스킬, 동적 스킬·참조 문서와 읽는 방법(§7)을 적는다.
- 블록 밖의 사용자 글은 1단계처럼 그대로 둔다.
- **갱신**(지시서 0027, 2026-11-26): 초기화된 프로젝트에서 검증에 충돌은 없지만 지침 블록이 현재 구성으로 만든 내용과 다르면(새 버전 TUI, 바뀐 훅 이름), 검증 화면에 [지침 갱신]을 보여 준다. 미리보기를 보여 주고 확인하면 관리 블록만 다시 쓴다. 미리보기에서 Esc를 누르면 쓰지 않고 검증 화면으로 돌아간다. 사용자가 고친 블록은 충돌이며 다시 쓰지 않는다.

## 6. 설치

### 6.1 스킬 (`skills`)

- 2026-11-23에 정한 스킬 설치 규칙(지시서 0021)을 유지한다. `npx skills add <source> [-s <skill>]`, `-a`·`-g`·`-y` 없음, 셸 없는 인자 배열, Windows는 `npx.cmd`, 이름 충돌 검사, 확인 화면에 명령 전체 표시.
- **터미널 넘기기:** 확인하면 TUI는 raw 모드와 대체 화면을 해제하고, stdin·stdout·stderr를 상속해 명령을 실행한다. 끝나면 Enter를 기다린 뒤 화면을 복원하고 종료 코드를 보여 준다. 에이전트 설치(§3)도 같은 방식이다.
- **갱신:** 설치한 스킬을 skills CLI로 갱신하는 동작을 제공한다. CLI의 갱신 명령과 범위는 구현 전에 공식 문서로 확인한다. 확인 후에만 실행하며, 백그라운드 예약 실행은 없다.
  - 구현(지시서 0029, 2026-11-27, skills CLI 1.9.0 문서 기준): 프로젝트 루트에 `skills-lock.json`이 있으면 초기화된 프로젝트의 검증 화면에 [스킬 갱신]을 보여 준다. `npx skills update -p`(프로젝트 스킬만, `-y` 없음이라 CLI의 질문은 사용자에게 간다)를 보여 주고, Enter를 누르면 터미널을 넘겨 실행한 뒤 종료 코드를 보여 준다. 이 버튼은 검증 충돌과 무관하다. 그 파일들은 skills CLI가 관리하며, 하네스는 `skills-lock.json`을 읽거나 쓰지 않는다. 읽기 전용 미리보기로 `npx skills check`를 안내한다.
- `installer`가 `skills-cli`가 아닌 항목은 `install` 문구를 보여 주고 사용자가 직접 실행한다.

### 6.2 위키 스킬 (`wiki_skills`, static)

- 게이트웨이 API v2(`GET /api/v2/documents/<uuid>?type=<type>`)로 페이지를 받아 1단계처럼 `.skills/<id>/`에 저장한다. `SKILL.md`/`SKILL_ko.md`, 부분 가져오기는 동의할 때만, `contentHash`는 `harness.lock.json`에 기록한다.
- `status: "archived"` 항목은 가져올 수 없다.
- 게이트웨이 토큰은 선택 사항이며 `.harness/local.toml`에 저장한다. `token_env`가 가리키는 환경변수의 토큰이 우선한다. 화면, 미리보기, 로그에 표시하지 않는다.

### 6.3 문서 (`docs`)

- `https://`로 문서를 받아 `<references>/<filename>`에 저장한다. 참조 문서 경로를 사용해야 한다.
- `sha256`이 없으면 경고하고 계속한다. `sha256`이 있는데 맞지 않으면 저장하지 않고 경고한다.
- 내용이 다른 기존 파일은 충돌이며 덮어쓰지 않는다.
- 내려받은 결과는 `harness.lock.json`에 기록한다.
- **흐름**(지시서 0028, 2026-11-27): 문서는 카탈로그 화면에서 고른다. 초기화된 프로젝트의 추가 작업 중에도 이 화면을 쓸 수 있다. 고르는 동안에는 받지 않고, 미리보기 직전에 내려받는다(명시적 `User-Agent`, 30초 제한). 내려받기 실패나 `sha256` 불일치는 미리보기에 보여 주고 제외하며, 나머지는 그대로 적용한다. 잠금 파일에 이미 있는 문서는 다시 고를 수 없다. 내려받은 문서의 갱신·삭제는 이후에 제공한다.

### 6.4 훅 (`hooks`)

- 훅은 참고 항목일 뿐이다. 제목, 요약, 선택적인 문서 링크를 담는다. TUI는 목록만 보여 주고 아무것도 설치하지 않는다.
- 지금은 자리만 잡아 둔다. 내장 `default.json`에는 예시 항목 하나만 있다.
- **훅 추가**(지시서 0026, 2026-11-26): 사용자가 항목을 고르면 ID를 `harness.toml` `[[hooks]]`에 기록하고, 지침 블록에 "훅(참고)" 절을 만들어 제목·요약·링크와 함께 "사용하는 훅은 에이전트 설정에 직접 추가하고 조정한다"는 안내를 적는다. 아무것도 설치하거나 실행하지 않는다. 구성에 더 이상 없는 ID는 그대로 두고 알 수 없음으로 표시한다.
- 위키 소스에서 목록 버튼은 구성의 `wiki_skills`를 보여 준다. 고르면 UUID, type, 이름이 채워지고, 보관된 항목과 이미 가져온 항목은 막는다.

## 7. 동적 스킬·참조 문서 (콘텐츠 서비스 클라이언트)

동적 콘텐츠는 콘텐츠 서비스에만 있다. 프로젝트에는 스텁과 목록만 둔다. 에이전트는 쓸 때마다 본문을 읽는다.

- **연결 설정:** `harness.toml`의 `[service]`에 `url`, `project`, `token_env`를 두고 Git으로 공유한다. `project.json`이 초깃값을 줄 수 있다.
- **토큰:** `token_env`가 가리키는 환경변수를 먼저 쓰고, 없으면 `.harness/local.toml`의 `[service] token`을 쓴다. 화면, 미리보기, 로그에 표시하지 않으며 추적 파일에 쓰지 않는다.
- **URL 규칙:** `https://`만 허용한다. 루프백 주소(`localhost`, `127.0.0.0/8`, `::1`)만 `http://`를 허용한다.
- **연결 화면:** URL, 프로젝트 ID, 토큰을 편집하고 연결을 시험한다. 먼저 상태 확인을, 다음에 인증된 접근을 확인한다. 연결됨, 인증 실패, 연결 불가, 호환되지 않는 버전을 구분해 보여 준다.
- **서비스 규약:** 엔드포인트, MCP 도구 이름, 응답 형식은 콘텐츠 서비스 프로젝트가 정한다. 그 프로젝트가 공개한 규약대로 구현하며 추측하지 않는다. TUI에 필요한 동작은 상태·규약 버전 확인, 동적 스킬 목록(이름, 설명), 동적 참조 문서 목록(경로, 제목)이다.
- **동적 스킬 스텁:** 선택한 동적 스킬마다, 선택한 에이전트마다 에이전트 스킬 디렉터리에 `SKILL.md`를 만든다. frontmatter의 `name`과 `description`은 서비스 목록 값이다. 본문에는 "따르기 전에 서비스(MCP 또는 REST)에서 현재 본문을 읽고, 실패하면 추측하지 말고 사용자에게 알린다"는 안내만 적는다. 스텁에는 본문 내용을 넣지 않는다. 스텁은 배치로 기록한다.
- **추적하지 않는 스텁:** 스킬 이름이나 설명도 공유하면 안 되면 사용자가 추적 안 함으로 지정할 수 있다. 그 스텁은 관리 `.gitignore` 블록에 추가한다.
- **동적 참조 문서:** 지침 블록에 선택한 참조 문서와 읽는 방법을 적는다. 본문은 저장하지 않는다.
- **이름 충돌:** 동적 스킬의 이름이 static 스킬이나 하네스가 배치한 스킬과 같으면(대소문자 무시) 충돌이다. 사용자가 하나를 고를 때까지 둘 다 배치하지 않는다.
- **MCP 등록:** 연결 화면은 선택한 각 에이전트의 프로젝트 MCP 설정(예: Claude Code `.mcp.json`)에 서비스를 MCP 서버로 등록한다. 토큰은 값이 아니라 환경변수 참조로만 쓴다. JSON 파일에서는 도구가 자기 서버 항목만 소유하고 이를 상태에 기록하며, 사용자가 그 항목을 고쳤으면 충돌이다. 파일 형식은 구현 전에 공식 문서로 확인한다. 형식을 확인하지 못한 에이전트는 수동 등록 안내를 보여 준다.
- **캐시 없음:** TUI는 동적 본문을 디스크에 쓰지 않는다. 설정 중에 서비스에 연결할 수 없으면 목록을 사용 불가로 표시하고, 기존 스텁은 바꾸지 않는다.

## 8. TUI

- 설치 화면에 항목별 상태를 보여 준다: 사용 가능, 설치됨, 가져옴, 보관됨, 충돌, 사용 불가.
- 설치 명령은 명시적인 확인 화면에서만 실행한다.
- 미리보기에는 모든 파일 변경, 모든 명령, 구성 출처, 충돌을 보여 준다.

## 9. 완료 기준

- 1단계 완료 기준을 모두 통과한다. 단, 이 단계에서 없앤 산출물 경로의 점 접두사 규칙은 제외한다(이슈 #36).
- `project.json`이 있으면 그것을 쓰고, 없으면 네트워크 요청 없이 내장 `default.json`을 쓴다. 둘을 병합하지 않는다.
- 잘못된 구성은 오류를 보여 주며 거부한다. 모르는 키, 지원하지 않는 버전, 중복 `id`, 옵션처럼 보이는 값, 빈 인자 배열이 해당한다.
- 에이전트: 대체 실행 파일로 감지가 동작한다. 선택한 에이전트 중 하나 이상이 설치될 때까지 다음으로 갈 수 없다. 확인 없이는 설치하지 않으며, 한 번에 여러 개를 설치하고, 종료 코드를 보고한다.
- 경로: 어떤 이름이든 받되, 안전 검사는 벗어남·중복·중첩을 계속 거부한다. 사용하지 않는 경로는 만들지 않는다. `.gitkeep`은 새로 만든 추적 디렉터리에만 만들고 덮어쓰지 않는다. `.gitignore` 블록은 지시서 루트 바로 아래의 `README.md` 외 Markdown 파일만 제외하고 하위는 제외하지 않는다. 디렉터리를 옮기거나 지우지 않는다.
- 스키마 1 `harness.toml`을 읽고 `output`을 값은 그대로인 채 `artifacts`로 바꾼다.
- 지침 파일은 에이전트 항목을 따르고 사용자 글을 유지한다.
- 스킬: 2단계(0021) 설치 테스트를 계속 통과한다. 갱신은 확인 후에만 실행한다.
- 문서: `sha256`이 맞지 않으면 저장하지 않고, 내용이 다른 기존 파일은 덮어쓰지 않는다.
- 동적 콘텐츠: 토큰을 표시하거나 추적 파일에 쓰지 않는다. 스텁에 본문이 없다. 이름 충돌은 배치를 막는다. 추적 안 함 스텁은 Git에서 제외된다. MCP 등록은 환경변수 참조만 쓴다. 테스트는 대체 서비스를 쓴다.
- 영어·한국어 문서는 같은 내용을 유지한다.
