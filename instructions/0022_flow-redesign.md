- 기존 `.output/`은 `.artifacts/`로 바뀐다(키 `artifacts`). 스키마 1 `paths.output`은 값은 그대로인 채 `paths.artifacts`로 읽는다(2026-11-24 결정).
- TUI는 경로를 만들기만 한다. 이동·이름 변경·삭제는 하지 않는다(2026-11-24 결정).

- 경로를 만들 때 Git 관리 대상 디렉터리에 빈 `.gitkeep`을 만들어 빈 디렉터리도 Git으로 관리되게 한다(2026-11-24 결정).
  - 대상: `instructions/`, `instructions/.completed/`, `docs/`, `references/` 등 Git 관리 대상 경로.
  - Git 제외 경로(`.artifacts/` 등)에는 만들지 않는다.
  - 새로 만드는 디렉터리에만 만든다. 이미 있던 디렉터리는 무관하다. 이미 있는 `.gitkeep`은 덮어쓰지 않는다.
  - 진행 중 지시서 제외: 지시서 루트 바로 아래의 `*.md`를 모두 제외하고 `README.md`만 남긴다(`/<instructions>/*.md`, `!/<instructions>/README.md`). 하위(`.completed/`)와 `.gitkeep`·`completed.log`는 추적된다(2026-11-24 결정).

## 초기 구성 파일 (2026-11-23 결정)
- `project.json`이 있으면 읽고, 없으면 `default.json`(기본 구성)을 읽는다.
- 목록: agents, skills, wiki-skill(static 내려받기), docs, hooks(지금은 더미). 연결 화면에서 dynamic skills·references의 서비스 연결(토큰 포함)을 설정한다.
- 설치 명령은 사용자 책임(`project.json`). TUI는 보여 주고 확인 후 셸 없이 실행한다.
- 토큰은 `.harness/local.toml`에 둔다(환경변수가 있으면 우선).
- 재현성은 Git이 맡는다. TUI는 초기 구성만 책임지고, 이후 갱신은 있으면 좋은 기능이다.
- `project.json`은 대상 프로젝트 루트에 두고 Git으로 공유한다. 있으면 `default.json`을 읽지 않는다(병합 없이 통째로 대체).
- 연결 화면이 에이전트별 MCP 설정(Claude Code `.mcp.json`, Codex 설정)에 서비스를 관리 블록으로 등록한다. 토큰은 환경변수 참조로만 적는다. 설정 형식은 구현 전에 공식 문서로 확인한다.
- 같은 이름의 스킬이 static과 dynamic 양쪽에 있으면 충돌로 막는다. 사용자가 하나를 고를 때까지 둘 다 배치하지 않는다.
- 서비스에 연결하지 못해 dynamic 본문을 받지 못하면 실패로 보고한다. 스텁에 "추측하지 말고 사용자에게 알린다"를 적고, 캐시는 두지 않는다.
