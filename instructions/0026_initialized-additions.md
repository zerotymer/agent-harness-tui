## 목표
이미 초기화된 프로젝트(`harness.toml` 있음)는 요약·검증 표기를 기본으로 하고, 추가 작업은 스킬 추가 설치와 훅 추가만 연다.

## 사용자 결정 (2026-11-26)
1. 초기화된 프로젝트는 단순 표기(요약·무변경 검증)만 한다. 경로·에이전트 변경, 재초기화는 열지 않는다.
2. 열 기능은 스킬 추가 설치와 훅 추가 설치뿐이다.
3. 훅은 지금은 단순 추가만 한다. 고른 훅을 참고 항목으로 기록하고, 사용자가 설치된 훅을 직접 에이전트 설정에 추가·조정하도록 안내만 한다. 훅 파일 설치·실행은 하지 않는다.

## 범위
- 포함:
  - 검증 화면에 [스킬 추가], [훅 추가] 버튼. 검증 결과에 충돌이 있으면 추가를 막는다
  - 스킬 추가: 기존 소스·스킬 화면을 그대로 쓴다(로컬 폴더, 위키 게이트웨이 UUID, 공개 스킬 설치). 경로·에이전트는 `harness.toml` 값으로 고정
  - 위키 스킬 목록: 위키 소스에서 [목록 불러오기]가 구성의 `wiki_skills`를 보여 준다. 고르면 UUID·type·이름이 채워지고, 보관된 항목·이미 가져온 항목은 막는다
  - 이미 있는 스킬 ID와 같은 이름은 추가하지 않는다(기존 가져오기 규칙)
  - 훅 추가: 구성의 `hooks` 중에서 골라 `harness.toml` `[[hooks]] id`로 기록한다(스키마 2에 선택 목록 추가). 지침 블록에 "훅(참고)" 절로 제목·요약·링크와 "설치된 훅을 에이전트 설정에 직접 추가하고 조정한다" 안내를 적는다
  - 구성에 없는 훅 ID는 `harness.toml`에 남기고 "알 수 없음"으로 표시, 지침에는 ID만 적는다
  - 추가 결과는 미리보기 → 적용(기존 적용 엔진, 백업, 모든 쓰기 성공 후 기록). 기존 관리 블록 갱신만 일어나야 한다
  - 새 프로젝트 플로우의 소스·스킬 단계에서도 같은 훅 선택 화면을 쓸 수 있다
  - 명세(`STEP_2`, 상태 규약) 영/한, 사용 문서 영/한
- 제외: 경로·에이전트 변경, 스킬 갱신·삭제, 훅 파일 설치·실행, docs 내려받기, 동적 스킬·참조 문서

## 테스트
- 초기화된 프로젝트: 검증 화면에서 스킬 하나를 추가해 적용하면 `.skills/<id>/`, lock, `harness.toml`, 지침 표가 갱신되고 나머지는 변경 없음
- 검증에 충돌이 있으면 추가 버튼이 막힘
- 위키 스킬 목록에서 고르기, 보관·이미 가져온 항목 차단
- 훅 추가: `harness.toml`에 기록, 지침에 안내 문구, 영/한 코드 스팬 동일
- 구성에 없는 훅 ID 유지·표시
- 스키마 2 `hooks` 없는 기존 파일 호환
