# instructions/ — 작업 지침서 운영 규칙

> 이 문서는 이 프로젝트의 **모든 후속 작업이 반드시 참고**하는 운영 지침입니다.
> 지시서를 실행하는 에이전트/작업자는 작업 시작 전에 이 문서를 먼저 읽습니다.

## 1. 목적

`instructions/`는 프로젝트를 단계적으로 구현하기 위한 **지시서(작업 지시)**를 보관·추적하는 공간입니다.

각 지시서는 한 단위의 실행 가능한 작업을 정의하며, 완료되면 보관 디렉토리로 이동하고 로그에 기록합니다.

## 2. 디렉토리 구조

```text
instructions/
├── README.md          # 이 문서: 작업 운영 지침 — 변경 시 모두에게 영향
├── completed.log      # 완료 지시서 누적 로그: UUID | 내용 | 일시
├── NNNN_name.md       # 진행 대기/진행 중 지시서 (순번 4자리 + 내용)
└── .completed/        # 완료된 지시서 보관 디렉토리
    └── <UUID>.md
```

## 3. 지시서 파일 규칙

- 파일명: `NNNN_<짧은-내용>.md` — `NNNN`은 4자리 순번(`0001`부터), `<짧은-내용>`은 지시 내용을 나타내는 kebab/스네이크 식별자.
- 한 파일 = 하나의 완결된 작업 단위. 순번은 권장 실행 순서이며, 의존성은 각 지시서의 `선행 조건`에 명시합니다.
- 완료된 지시서는 원래 파일명을 유지하지 않고 `instructions/.completed/<UUID>.md`로 이동합니다.
- 모든 산문/커뮤니케이션은 한글, 코드·주석·식별자는 영어(전역 컨벤션)를 사용합니다.

### 지시서 표준 구조 (템플릿)

```markdown
# NNNN — <제목>

> 엔티티 UUID: <uuid>   (로컬에서 생성)
> 상태: TODO | IN_PROGRESS | DONE
> 브랜치: feature/<name>/<uuid>   (작업 시작 시 기입)

## 목표
<무엇을, 왜>

## 선행 조건
<완료되어 있어야 할 지시서 번호 / 외부 의존>

## 범위
- 포함:
- 제외:

## 작업 항목
1. ...

## 산출물
- <파일/문서/엔드포인트 등 + 각 산출물 UUID>

## 완료 기준 (DoD)
- [ ] 테스트 포함
- [ ] 테스트 예외 사유 명시 (문서/설정/비기능 변경 등 테스트가 불필요한 경우)
- [ ] 가드레일 준수 확인 (§7)
- [ ] 브랜치에서 작업 후 PR 준비 (main 직접 push 금지)

## 가드레일 체크
<이 작업이 §7 범위 제외 사항을 건드리지 않는지>
```

## 4. 지시서 생명주기

1. **생성**: `instructions/NNNN_name.md`로 작성합니다. 상태는 `TODO`입니다. 새 단위이므로 UUID를 부여합니다(§5).
2. **착수**: 상태를 `IN_PROGRESS`로 변경하고, 브랜치를 생성한 뒤(§6) 브랜치명을 지시서에 기입합니다. 세션 기록을 갱신합니다(§8).
3. **완료**: 완료 기준 충족 → 상태 `DONE` → 파일을 `instructions/.completed/<UUID>.md`로 **이동** → `completed.log`에 1줄 추가합니다.
4. **변경/재개**: 완료된 지시서를 다시 손대야 하면 새 순번의 후속 지시서를 만듭니다. 완료 기록은 보존합니다. UUID는 동일 단위면 재사용·갱신합니다.

### completed.log 형식

탭/파이프 구분, 한 줄에 하나를 기록합니다. 최신 항목은 아래로 append합니다.

```text
UUID | 내용 | 일시(YYYY-MM-DD HH:MM:SS +0900)
```

## 5. UUID 식별자 부여 (필수)

- 모든 지시서와, 고정 참조가 필요한 다른 단위에 안정적인 UUID를 부여합니다.
- 작업 전에 로컬에서 생성합니다. 예: `python3 -c "import uuid;print(uuid.uuid4())"`. 외부 레지스트리는 사용하지 않습니다.
- UUID는 **불변**입니다. 같은 단위가 바뀌어도 UUID를 유지하고 새로 만들지 않습니다.
- 부여한 UUID는 관련 지시서·참조 문서·코드에 머리말이나 주석으로 기입합니다.

## 6. 브랜치 전략 (기능 추가/수정 필수)

> 스킬: `.skills/git-branch-guideline` (UUID `e03f48fb-3e00-41d7-b99d-c32854567d67`)

- `main`·`staging`에는 직접 commit/push **금지**입니다. 기능 작업은 항상 브랜치에서 진행하고 PR을 준비합니다.
- 기능: `feature/<name>/<uuid>` (`main` 기준 분기)
- 버그: `fix/<name>/<uuid>`
- 임시: `temp/<YYYYMMDD-HHmmss>-<uuid>`
- `<uuid>`에는 지시서 UUID의 앞 8자리를 사용해 지시서와 브랜치를 연결합니다.
- 작업 완료는 PR 준비 상태로 마무리합니다. 기능 PR은 테스트를 포함해야 하며, 문서/설정/비기능 변경처럼 테스트가 불필요한 경우에는 예외 사유를 명시합니다.

## 7. 범위 가드레일 (절대 준수)

모든 지시서/코드/제안에 적용합니다.

- **금지**: IP 은닉·익명화, 접근 제한 우회, 인증·결제 장벽 우회, 탐지·차단 회피, 회피 목적 트래픽 분산, 제3자 장비 무단 수집, 약관·법 위반 자동화.
- **필수**: robots.txt·약관 존중, 도메인별 rate limit, SSRF 방지(localhost·사설/link-local IP·클라우드 metadata 차단, 리다이렉트 후 IP 재검증, 포트 allowlist), 모든 노드 통신 TLS + 상호 신원 검증, 명령 **allowlist만 허용**(노드 임의 코드 실행 금지), 관리자 작업 감사 로그.
- 지시 내용이 가드레일을 약화하거나 위반하면 **구현하지 말고 먼저 보고**합니다.

## 8. 세션 기록 (새 세션 시작 시 필수)

> 스킬: `.skills/project-session` (UUID `b3230cd0-6081-4570-9bda-183543f585e9`)

- 새 에이전트 세션 시작 시 `.claude/session`(현재 세션 상세) 및 `.claude/session.log`(`<session-id> - <topic>` 한 줄, Codex는 `.codex/session*`)를 생성·갱신합니다.
- 이 파일들은 **로컬 런타임 상태**이며 Git에 커밋하지 않습니다(`.gitignore` 처리).
