## 목표
0002~0009 기능을 6단계 TUI 흐름으로 연결한다.

## 규칙 구분
- 아래 요구사항은 TUI가 **대상 프로젝트에 적용하는 제품 동작**이다. 이 저장소의 작업 규칙(`CLAUDE.md`, `.skills/`)과 혼동하지 않는다.
- 테스트는 임시 디렉터리에 대상 프로젝트를 만들어 검증한다. 이 저장소의 `instructions/`, `.gitignore`, 지침 파일을 픽스처로 쓰지 않는다.

## 선행 조건
- 0002 ~ 0009

## 범위
- 포함:
  - 흐름: ① 루트·기존 설정 확인 ② 참조·산출물 경로·백로그 설정(고정 경로 명시 표시) ③ 에이전트·배치 방식 선택 ④ 소스 탐색·미리보기·스킬 선택 ⑤ 디렉터리·파일·지침 블록·Git 규칙·충돌 미리보기 ⑥ 명시적 적용 후 생성·보존·건너뜀·실패 보고
  - 키보드만으로 조작 (SSH 환경), 창 크기 변경, 한글 표시·입력(문자 폭 처리)
  - 어느 단계에서든 취소, 적용 전에는 쓰기 없음
  - 오류·패닉 후 터미널 복원
  - 대화형 터미널이 없으면 대기하지 않고 명확한 오류로 종료
  - 다시 그릴 때 네트워크·디스크 조회 반복 금지
  - 이미 초기화된 경우: 요약과 조회·무변경 검증만 제공, 재초기화로 2단계 변경 기능 우회 금지
- 제외:
  - 2단계 업데이트·모드 화면

## 작업 항목
1. 화면 상태 머신 (터미널과 분리)
2. 단계별 화면
3. 터미널 초기화·복원
4. 테스트: 상태 전이(Ratatui 테스트 백엔드), 취소 시 무변경, 비대화형 실패, 초기화된 프로젝트 무변경 검증
