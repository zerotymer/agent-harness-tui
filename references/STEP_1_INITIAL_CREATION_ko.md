# 1단계: 최초 하네스 생성

## 목표 및 경계

> 2026-11-24: 구현을 Node.js(TypeScript + Ink, 지시서 0025)로 옮긴다. 아래의 Rust·Ratatui·Crossterm 표현은 1단계를 만들고 인수한 방식의 기록이며, 규칙 자체는 계속 적용된다.

프로젝트 초기 하네스를 구성하는 Rust 독립 실행형 TUI를 만든다. 대상 프로젝트 루트에서 실행하며 Ratatui·Crossterm을 사용한다. Linux 서버를 우선 대상으로 하고 Windows·macOS 네이티브 실행을 지원한다.

이 지시서는 이 저장소에서 구현한다. 기존 사용자 파일을 보존한다. 이 단계에는 worktree 관리, Worktrunk, Docktree, 실행 모드, 실행형 훅, 서비스 관리, 범용 하네스 업데이트를 추가하지 않는다. 대신 3단계 업데이트에 필요한 기준 상태를 저장한다.

## 1. 프로젝트 루트 및 경로 규칙

- 현재 실행 디렉터리를 프로젝트 루트로 취급한다. 상위 경로를 탐색해 루트를 몰래 변경하거나, 브랜치를 전환하거나, Git을 자동 초기화하지 않는다.
- 비교 시 경로를 정규화하고 공유 설정에는 이식 가능한 프로젝트 상대 경로를 저장한다. 입력 시 공백·한글·Windows 드라이브 경로를 지원한다.
- 관리·공유 경로는 프로젝트 루트 내부로 제한한다. `..` 또는 심볼릭 링크 해석 결과의 루트 이탈, 중복 목적지, 관리 디렉터리 간 중첩, 기존 파일과의 충돌을 거부한다.
- 상대 경로는 실행 파일이나 설정 파일의 상위 디렉터리가 아니라 프로젝트 루트에서 해석한다.
- 1단계는 프로젝트 로컬 상태만 사용한다. 다른 worktree의 상태를 탐색·복사·동기화하지 않는다.

| 항목 | 기본 경로 | 변경 가능 여부 | Git 정책 |
| --- | --- | --- | --- |
| 진행 중 지시서 | `instructions/` | 사용자 설정 가능(지시서 루트) | 포함 |
| 완료 지시서 | `instructions/.completed/` | 지시서 루트를 따름 | 포함 |
| 완료 로그 | `instructions/completed.log` | 지시서 루트를 따름 | 포함 |
| 참조 문서 | `references/` | 사용자 변경 가능 | 포함 |
| 임시 산출물(로컬, 공유 안 함) | `.output/` | 사용자 변경 가능 | 제외 |
| 스킬 원본 | `.skills/` | 1단계에서 기본값 고정 | 포함 |
| 선택적 백로그 | `instructions/agent.db` | 사용 여부만 선택, 지시서 루트를 따름 | 제외 (`agent-db.sh`/`agent-db.ps1` 스크립트는 포함) |

1단계는 산출물 디렉터리 이름이 점으로 시작해야 했다. [2단계 명세](STEP_2_SETUP_FLOW_ko.md) §4에서 이 규칙을 없앴다(이슈 #36). 모든 경로는 사용자가 정하며, 산출물 디렉터리는 임시 산출물 디렉터리가 된다. Windows 숨김 속성은 별도 플랫폼 처리 사항이며 이름 앞의 점만으로 설정되지 않는다. 선택한 숨김 속성을 적용할 수 없다면 이유를 안내하고 결과에 표시한다.

## 2. 생성할 지시서 운영 규칙

아래 규칙을 프로젝트 지침으로 생성한다. 초기화 도구 자체를 작업 실행·지시서 완료 처리 시스템으로 구현하지 않는다.

- 이 절의 `instructions/`는 설정한 지시서 루트(기본 `instructions/`)를 뜻한다.
- 지시서는 한국어로 작성하는 Markdown 문서이며, 지시서 하나당 파일 하나(`instructions/NNNN_짧은-이름.md`)를 쓴다. `NNNN`은 `0001`부터 시작하는 4자리 순번이다. 지시서 머리말에는 고정된 UUID와 상태(`TODO`, `IN_PROGRESS`, `DONE`)를 적는다. 지시서는 번역하지 않는다. 영어·한국어 쌍은 에이전트가 참고하는 참조 문서·스킬·지침 문서에만 적용한다.
- 진행 중·완료 지시서 모두 Git으로 관리한다.
- 명시적으로 작업을 완료 처리할 때 상태를 `DONE`으로 바꾸고 파일을 `instructions/.completed/<UUID>.md`로 이동한다. 에이전트 응답이나 세션 종료를 완료로 간주하지 않는다.
- 완료된 지시서마다 `instructions/completed.log`에 기록 순서대로 한 줄을 추가한다. 형식은 `UUID | 내용 | 오프셋 포함 일시`다.
- 지시서 UUID는 독립 작업 사본 사이에서도 고유해야 한다. 로그의 줄 순서와 `NNNN` 순번은 로컬 순서이며, Git 브랜치 전체의 고유 번호나 전역 시간순을 보장하지 않는다.
- 기록 주체는 로그를 잠그고 기존 기록 덮어쓰기를 방지한다. 이력을 몰래 버리거나 번호를 재작성하지 않고 병합 충돌을 드러낸다. worktree 간 조정은 3단계 범위다.
- 초기화 시 로그가 없으면 빈 파일을 만들 수 있으나, 기존 로그를 비우거나 초기화를 작업 이벤트로 기록하지 않는다.
- `agent.db`는 선택 사항이며 지시서 루트에 둔다. 사용 여부와 프로젝트 상대 경로를 저장한다. 사용하도록 선택하면 사용자가 제공한 스키마(GitHub 이슈 #21)로 만든다. 에이전트가 할 작업을 담는 `backlog` 테이블과 지시서 상태를 담는 `instructions` 테이블이 있고, 둘 다 `status`(기본 `created`), 생성·수정 시각, `created_by`/`updated_by`를 가진다. 상태 인덱스와 WAL 모드도 설정한다. 같은 위치에 사용자의 `sqlite3` CLI를 호출하는 관리 스크립트 `agent-db.sh`(bash)와 `agent-db.ps1`(PowerShell)을 만든다. DB와 스크립트는 없을 때만 만든다. 기존 DB를 마이그레이션하거나 수정하지 않고, 사용자가 고친 스크립트를 덮어쓰지 않는다.
- 완료된 지시서의 기준은 계속 `completed.log`다. 스크립트는 이 로그를 읽어 DB를 맞추고, 로그에는 한 줄을 추가하기만 한다. 변경자는 `AGENT_DB_ACTOR`(기본 `agent`)로 기록한다.

## 3. 공유 설정 및 로컬 상태

명시적인 스키마 버전과 함께 다음 초기 파일 규약을 사용한다.

| 파일 | 역할 | Git 정책 |
| --- | --- | --- |
| `harness.toml` | 경로, 대상 에이전트, 외부 소스 식별자, 선택 스킬, 배치 방식, 백로그 옵션 | 포함 |
| `harness.lock.json` | 확정된 소스 ID, 리비전·내용 해시, 가져온 파일 목록 | 포함 |
| `.harness/state.json` | 마지막 성공 적용, 관리 파일·블록, 기준 해시, 복사본 매핑 | 제외 |
| `.harness/backups/` | 도구가 변경한 파일의 로컬 복구 사본 | 제외 |

- 공유 파일에 토큰, 환경별 절대 경로, 일시적 서비스 할당 정보를 저장하지 않는다.
- 소유권은 파일 또는 관리 블록 단위로 기록한다. 기존 사용자 파일에 블록 하나를 추가했다는 이유로 전체 파일을 도구 소유로 취급하지 않는다.
- clone 후 로컬 상태가 없다는 이유로 기존 파일을 덮어쓰지 않는다. 설정·잠금 정보를 조사하고 소유권을 확인할 수 없다면 충돌 해결을 요구한다.
- 예정한 쓰기가 모두 성공한 뒤 성공 상태를 기록한다. 중간 실패 시 가능한 범위에서 변경 파일을 복구하고 잔여 변경을 보고한다. 파일 시스템이 제공하지 않는 디렉터리 전체 트랜잭션 보장을 주장하지 않는다.

## 4. 외부 스킬 및 참조 문서

- 스킬 문서·동봉 파일의 목록 조회, 검색, 미리보기, 가져오기를 담당하는 소스 연결 경계를 둔다.
- 주 연계 대상은 `md.zerotymer.net` Wiki.js이며, 읽기 전용 게이트웨이 `https://md-gw.zerotymer.net`을 통해서만 읽는다. 검증된 규약은 게이트웨이 API v2(`wikijs-agent-gateway` 2.0.0, 2026-11-20 `/api/v2/openapi.json`으로 확인)다.
  - `GET /api/v2/documents/<uuid>[?type=<type>]`. UUID는 대소문자를 구분하지 않는다. `type`은 Wiki.js 경로 접두어이며 여러 단계일 수 있다(`skill`, `claude/hook`). 사용자가 줄 때만 전달한다.
  - 토큰은 선택 사항이다. 지금은 읽기에 인증이 필요 없다. 설정한 환경변수에 토큰이 있으면 `Authorization: Bearer <token>`을 보내고, 401/403이면 토큰이 필요하다고 안내한다.
  - 없는 페이지는 `page-not-found` 유형의 404 problem 문서로 온다. 그 밖의 404는 페이지 없음이 아니라 게이트웨이 API 불일치로 보고한다.
  - 응답의 `pages.en`, `pages.ko`에는 각각 `content`(Markdown)와 `contentHash`가 있다. 없는 언어는 `null`이며, 두 언어가 모두 없으면 `PAGE_NOT_FOUND`다.
  - `pages.en.content`는 `SKILL.md`, `pages.ko.content`는 `SKILL_ko.md`로 내용 변경 없이 저장한다. 프런트매터 활용 방식(스킬 이름 추출, Wiki.js 페이지 프런트매터 제거 등)은 추후 정한다. 한 언어만 있으면 사용자가 부분 가져오기를 수락한 경우에만 가져온다. 빈 파일을 쓰지 않는다.
  - Wiki.js GraphQL API를 직접 호출하거나 `md.zerotymer.net` HTML을 수집하지 않는다. 그 사이트는 사람이 확인하는 용도로만 쓴다.
  - 목록 조회·검색은 아직 문서화된 REST 규약이 없다. 규약을 제공받기 전까지 네트워크 호출 없이 고정 항목을 돌려주는 더미로 대신하고, 더미임을 명확히 표시하며, 가져오기는 UUID로 한다. endpoint를 임의로 만들지 않는다.
- 외부 API 정보가 없더라도 초기화할 수 있도록 로컬 디렉터리 소스를 제공한다.
- 외부 목록은 동적으로 조회한다. 선택한 내용을 `.skills/`에 가져오고 소스 식별자와 리비전 또는 해시를 보존한다. 원격 내용이 변경됐다는 이유로 설치된 스킬을 변경하지 않는다.
- 일반 참조 문서는 `references/`, 스킬 원본 패키지는 `.skills/`에 보관한다. 동봉된 스크립트·템플릿도 보존하되 가져오는 과정에서 실행하지 않는다.
- 네트워크 시간 제한과 명확한 오류를 제공한다. 캐시 대체 기능이 있다면 저장 시점을 보여주고 사용자가 선택하게 한다. 캐시를 최신 내용처럼 표시하지 않는다.
- 인증 정보는 로컬 환경변수·자격 증명 참조로 읽는다. 값을 Git 관리 설정·생성 지침·미리보기·로그에 기록하지 않는다.
- 목적지를 벗어나는 패키지 파일 경로를 거부한다. 원문 언어를 보존하고 없는 번역본을 만들어내지 않는다.

## 5. 에이전트 지침 및 스킬 배치

- 선택한 에이전트에 대해 `AGENTS.md` / `AGENTS_ko.md`, `CLAUDE.md` / `CLAUDE_ko.md`를 생성한다.
- 단수 `AGENT.md`가 아닌 `AGENTS.md`를 사용한다. 사용자 홈 전역 지침이 아니라 프로젝트 전체 지침이다.
- 같은 구조화된 하네스 설정에서 에이전트별·언어별 지침을 생성하여 정책을 동등하게 유지한다.
- 경로 의미, 지시서 수명주기, 로그 정책, 참조 문서·스킬 탐색, 산출물 정책, 백로그 옵션, Git 정책을 포함한다. 항상 읽는 루트 지침에 스킬 본문을 합치지 않고 용도·위치를 안내한다.
- 기존 파일에는 제한된 관리 블록 삽입을 미리 보여준다. 블록 밖의 내용은 보존한다. 마커 충돌·손상 시 전체 파일 교체 대신 충돌로 처리한다.
- 에이전트별 연결부에서 스킬 복사·참조 배치를 선택한다. 현재 탐색 규칙과 참조 지원을 검증한다. 지침에 경로를 적는 것만으로 에이전트가 스킬을 자동 탐색한다고 판단하지 않는다.
- `.skills/`를 공유 원본으로 유지한다. 배치 파일 매핑과 해시를 기록하고 기존 무관한 스킬을 덮어쓰지 않는다. 중복 생성하는 배포 파일에는 Git 정책을 명시하며, 기본은 다시 생성 가능한 복사본을 ignore 처리한다.
- 미지원 배치 방식은 이유와 함께 선택 불가로 표시한다. Windows에서 심볼릭 링크 권한을 암묵적으로 요구하지 않는다.
- 프로젝트 지침은 정책을 표현하며, 파일 시스템·명령 실행 권한을 그 자체로 강제하지 않는다.

## 6. Git 정책

진행 중·완료 지시서, `completed.log`, 참조 문서, 스킬 원본, 공유 설정·잠금 파일, 루트 지침을 추적한다.

설정된 산출물 경로, `.harness/`, 백로그 DB와 그 `-wal`·`-shm`·`-journal` 파일, 필요한 재생성 가능 배포 복사본에 대한 제한된 `.gitignore` 규칙을 생성한다. DB 사용 전에도 백로그 경로를 제외해 나중에 실수로 추가하지 않게 한다. 무관한 기존 ignore 규칙을 보존한다.

Git 사용이 가능하면 하위·상위 ignore 규칙의 영향도 확인한다. 공유 경로가 제외된다면 보고한다. ignore 목적지가 이미 추적 중이면 `.gitignore`가 추적을 해제하지 않는다는 점을 안내하고 인덱스를 자동 변경하지 않는다. 커밋·푸시하지 않는다. 빈 디렉터리는 Git 객체가 아니므로 추적 파일이 없는 디렉터리가 공유된다고 안내하지 않는다.

## 7. TUI 흐름

> 2026-11-26(지시서 0023): 2단계에서 이 순서가 바뀐다. 에이전트(감지·선택·설치)가 먼저 오고, 루트 화면은 없다. 프로젝트 루트와 구성 출처는 모든 화면의 머리글에 표시한다. 이미 초기화된 프로젝트는 여전히 아래의 요약과 무변경 검증만 받는다.

1. 현재 프로젝트 루트와 기존 설정 확인
2. 지시서·참조·산출물 경로 및 백로그 사용 여부 설정. 고정 경로는 명시적으로 표시
3. 에이전트 및 지원되는 스킬 배치 방식 선택
4. 소스 탐색, 미리보기, 초기 스킬 선택
5. 디렉터리·파일·관리 지침 블록·Git 규칙·충돌 미리보기
6. 명시적으로 적용하고 생성·보존·건너뜀·실패 항목 보고

SSH에서 키보드만으로 사용, 창 크기 변경, 한글 표시·입력, 취소, 실패 후 터미널 복원을 지원한다. 화면을 다시 그릴 때마다 네트워크 조회를 하지 않는다. 대화형 터미널이 없으면 대기하지 않고 명확히 실패한다.

이미 초기화된 상태라면 요약과 조회·무변경 검증을 제공한다. 재초기화를 통해 2·3단계 변경 기능을 우회 제공하지 않는다. 같은 초기화를 반복해도 관리 블록·스킬·ignore 항목이 중복되지 않아야 한다.

## 8. 완료 기준

- 로컬 소스를 사용하면 관리자 권한이나 필수 네트워크 연결 없이 임시 프로젝트를 초기화할 수 있다.
- 재실행 후 설정과 경로 해석이 유지되며 두 언어 지침의 진행 중·완료 지시서 정책이 일치한다.
- 기존 지침·로그가 보존되며 반복 초기화가 관리 항목을 중복 생성하지 않는다.
- 경로 이탈·충돌 거부, 생성 지침 경계, 패키지 경로 이탈 거부, Git ignore 동작, 적용 중단 후 복구를 의미 있는 테스트로 검증한다.
- 대상 에이전트 연결부를 최신 공식 규약과 대조한다. 미지원 방식을 지원한다고 주장하지 않고 기록한다.
- Linux·Windows·macOS에서 루트·경로·터미널 동작을 검증하며 실제 검증하지 못한 플랫폼을 명시한다.
- worktree·서비스 관리와 실행형 훅을 포함하지 않으며, 제공된 `agent.db` 스키마 외의 SQLite 스키마를 만들지 않는다.
